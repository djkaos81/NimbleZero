# Building

## Host requirements

- Linux x86-64 (native, VM, or **WSL2**). Build inside the Linux filesystem (`~/...`), not
  under `/mnt/c`: Windows filesystems are case-insensitive and Buildroot will fail there.
- About 25 GB of free disk for all variants, 8 GB RAM recommended.
- Packages (Debian/Ubuntu names):
  `build-essential git bc bison flex cpio rsync unzip file wget python3 libncurses-dev
  libssl-dev libelf-dev xz-utils`
- For the tests: `mtools e2fsprogs device-tree-compiler binutils qemu-system-arm dosfstools dpkg-dev zstd`
- For the desktop simulator: `libsdl2-dev`

## One command

```sh
./build.sh minimal            # -> artifacts/cardputerzero-minimal.img(.xz) + .sha256 + manifest + image-check report
./build.sh compat             # image with dpkg + M5Stack compatibility layer + native launcher
./build.sh minimal compat     # both
```

`build.sh` clones Buildroot at the pinned tag (verifying the commit id), configures the
variant from `external/configs/nz_<variant>_defconfig`, builds, checks the kernel
configuration, runs the structural image test and writes checksums and a manifest.
A first build takes roughly 40-60 minutes per variant on 8 cores (a 2-core machine needed
about 75 minutes); later builds are incremental.

## Offline builds

```sh
./build.sh fetch minimal compat      # with network: download every source into ./dl
NZ_OFFLINE=1 ./build.sh minimal      # later, without network
```

`fetch` runs Buildroot's `make source` for the variant. With `NZ_OFFLINE=1` the build is
configured so that any attempt to download fails instead of reaching the network. `./dl`
plus the `./buildroot` checkout is everything needed; copy both to another machine to build
there without network. (`NZ_OFFLINE=1` has not been exercised end to end yet – see
`KNOWN-ISSUES.md`.)

## What is pinned

| Input | Pin | Where |
|---|---|---|
| Buildroot | tag 2026.02.3, commit `679b9ead` (checked by `build.sh`) | `versions.env` |
| Toolchain | Bootlin `aarch64--glibc--stable-2025.08-1` (gcc 14.3.0, glibc 2.41, binutils 2.44), sha256 in Buildroot | Buildroot |
| Kernel | `raspberrypi/linux` tag `stable_20261103` = commit `0b417245…` (6.18.60), sha256 in `external/patches/linux/linux.hash` | `configs/fragments/common.frag` |
| Boot firmware | `raspberrypi/firmware` commit `063bcab6…`, sha256 in Buildroot | Buildroot |
| Wi-Fi/BT firmware | `LibreELEC/brcmfmac_sdio-firmware-rpi` commit `6596d332…`, sha256 in Buildroot | Buildroot |
| Board drivers + overlays | `m5stack/m5stack-linux-dtoverlays` commit `4f7aeee9…`, sha256 in `external/package/nz-drivers/nz-drivers.hash` | `nz-drivers.mk` |
| dpkg | 1.22.22 (Debian trixie), sha256 from the Debian `.dsc` | `external/package/dpkg/` |
| Every other package | version + hash from Buildroot 2026.02.3 | Buildroot |

`BR2_DOWNLOAD_FORCE_CHECK_HASHES=y` is set: a source archive without a matching hash stops
the build.

Reproducibility level: inputs are fully pinned and the build is scripted, so two builds
produce functionally identical images. They are **not** guaranteed to be bit-identical
(`BR2_REPRODUCIBLE` is not enabled; file timestamps and the ext4 UUID differ).

## Repository layout

```
build.sh, versions.env        one-command build, pins
external/                     Buildroot BR2_EXTERNAL tree
  configs/fragments/*.frag    the source of the defconfigs (edit these)
  configs/nz_*_defconfig      generated by scripts/gen-defconfigs.sh
  board/cardputerzero/        config.txt, cmdline, kernel fragment, genimage, post-build/-image, rootfs overlay
  package/nz-drivers          M5Stack kernel modules + overlays + firmware blobs
  package/nz-diag             diagnostic UI
  package/nz-launcher         native launcher
  package/nz-compat           dpkg seeding, dpkg guard, shims, M5 device aliases
  package/dpkg                Debian dpkg (C tools)
  patches/                    hashes for the pinned kernel
sdk/                          nzui.h UI layer, app template, example apps, packaging tool
scripts/                      generators (kernel fragment, defconfigs, manifest), deb inspection
tests/                        image checker, kernel-config checker, QEMU boot harness, lifecycle tests
docs/                         documentation and recorded results
```

## Changing the configuration

- Packages: edit a fragment in `external/configs/fragments/`, run
  `scripts/gen-defconfigs.sh`, rebuild.
- Kernel options: edit the allowlist or the additions in `scripts/gen-kernel-fragment.py`,
  regenerate with
  `scripts/gen-kernel-fragment.py <linux>/arch/arm64/configs/bcm2711_defconfig > external/board/cardputerzero/linux.fragment`.
  `tests/check-kernel-config.sh` fails the build if a required option disappears.
- Interactive: `make -C buildroot O=$PWD/out/<variant> BR2_EXTERNAL=$PWD/external menuconfig`.

## How this tree was built so far

All images delivered with this repository were compiled in a hosted Linux container (2 cores),
not on the owner's PC. `./build.sh minimal` was verified there end to end; see
`KNOWN-ISSUES.md` item 2 for what was not. The one-command build has not been run under
WSL2 yet.
